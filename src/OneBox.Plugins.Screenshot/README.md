# 截图 · OneBox 内置小工具

**全屏、区域、滚动截长图，配合贴图置顶、贴图标注与文字识别（含在图上划选取字）。**

- 插件 id：`screenshot`
- 数据目录：`data/plugin-state/screenshot/`
- 源码：`src/OneBox.Plugins.Screenshot/`（界面与宿主交互）+ `src/OneBox.Plugins.Screenshot.Core/`（纯逻辑，可单测）
- 平台与本项目其他小工具见[平台 README](../../README.md)

## 功能

- **区域截图**：拖动选区，实时显示像素尺寸；鼠标悬停自动吸附到窗口边框（`Space` 切换吸附），单击直接抓整窗，`Ctrl+A` 抓整个虚拟屏幕，`Enter` 确认、`Esc`/右键取消
- **全屏截图**：一次抓下所有显示器组成的虚拟屏幕（多屏负坐标正确处理）
- **滚动截长图**：在区域里滚轮下滚，逐帧用带容差的行剖面定位重叠区并拼接，到达底部/高度上限自动停止，过程中可随时点「完成并保存」
- **贴图置顶**：截图后立刻以无边框窗口钉在屏幕上，`WS_EX_TOPMOST | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`，并**每秒重申一次置顶**（只确认仍在置顶组，不改动组内层叠次序，避免多张贴图互相插队）——切换应用、甚至别的置顶窗口都不会盖住它。可拖动、滚轮缩放、右下角等比缩放，支持多张同时贴图
- **贴到原位**：区域截图与滚动截长图生成的贴图会**贴回刚才截取的位置附近**（下方放不下就转到上方），一眼就能和原内容对照
- **工具条在贴图外**：所有操作按钮收在图片**下方**的专属横条里，始终可见又不遮挡图片本身；第一行左侧显示尺寸、缩放比例与置顶状态
- **贴图编辑栏**：图片下方第二行是编辑栏。**选择工具**可切换矩形/椭圆边框，**箭头**可从一个位置指向另一个位置，二者共用颜色与粗细设置；**文字标注**可设置颜色与字号，点击图片弹出文本框输入说明文字；**撤销**按添加顺序逐步移除标注。三个工具都是单次操作：画完一个框/箭头或提交一次文字后自动退出，拖动贴图与双击关闭立即恢复。标注随贴图一起缩放，复制、另存为与 OCR 都使用包含标注的合成图
- **保存**：截图只做预览，**不再自动落盘**；点「保存」弹出「另存为」对话框，初始目录与文件名按设置预填（PNG / JPEG 可调质量，文件名支持时间占位符），由你亲自决定存到哪里，不会悄悄往默认目录堆文件
- **删除贴图**：工具条 🗑 或 `Del` 关闭预览；若这张贴图已经保存过文件，会先问一句要不要连文件一起删掉
- **文字识别（双引擎）**：优先用 PaddleOCR（PP-OCRv5 mobile 中文模型，离线 ONNX 推理，小字错字明显更少）；模型缺失或识别异常时自动回退系统自带的 `Windows.Media.Ocr` 引擎，**两条路都离线可用**。结果为中文时自动去掉字间空格，识别文本默认复制到剪贴板
- **长图也能识别**：PaddleOCR 走**短边自适应**放大，不把长边压到 1024，因此滚动截长图产出的几千像素长的图不会因为被整体缩小而识别不出文字（详见实现要点）
- **划选取字**：在贴图上像文档一样拖动鼠标划选文字（**字符级**，可跨行），松开即复制，支持双击选词、`Ctrl+A` 全选、`Ctrl+C` 复制。识别结果按词框缓存在贴图上，划选是纯几何计算，不重复识别
- **不抢焦点**：贴图窗平时点击不激活，不影响你正在编辑的内容（文字标注输入时临时允许激活，提交/取消后恢复）；截图前会自动隐藏自己的贴图与设置窗，避免入镜

## 全局热键

在截图设置页（托盘子菜单「截图设置…」）里可改；改键后由宿主重新注册。

| 热键 | 功能 |
|---|---|
| `Ctrl+F1` | 区域截图 |
| `Ctrl+F2` | 全屏截图 |
| `Ctrl+F3` | 滚动截长图 |
| `Ctrl+Alt+T` | 识别剪贴板里的图片文字 |

被其他软件占用的热键会在设置页顶部提示，但不影响其余热键。

## 贴图窗快捷键

| 操作 | 行为 |
|---|---|
| 拖动图片 | 移动贴图位置 |
| 滚轮 | 以 10% 步进缩放 |
| 双击图片 | 关闭本贴图（恢复原始尺寸请用 `Alt+0` 或工具条按钮） |
| `Alt+T` | 切换置顶 / 取消置顶 |
| `Alt+C` / `Alt+S` / `Alt+O` | 复制 / 保存 / 识别文字 |
| `Alt+X` | 进入 / 退出「选择文字」模式 |
| `Ctrl+Z` / `Alt+Z` | 撤销上一步贴图标注 |
| `Alt+0` | 恢复原始尺寸 |
| `Del` | 删除此截图（若已保存过文件，询问后一并删除） |
| `Esc` | 取消文字输入 → 退出标注工具 → 退出选择文字 → 关闭本贴图 |

贴图下方有两行专属横条（不遮挡图片）：第一行左侧显示尺寸/缩放/置顶状态，右侧依次是 📌 置顶、✕ 关闭、🗑 删除、📋 复制、💾 保存、🔤 识别、📝 选择文字、↺ 恢复原始大小、↗ 保存并用系统看图程序打开；第二行是编辑栏，包含选择工具、箭头、文字标注、颜色/粗细/字号设置与 ↶ 撤销。保存完成后会自动用默认看图程序打开刚写出的文件。

## 在贴图上划选取字

点工具条上的 📝 进入「选择文字」模式（或按 `Alt+X`），首次进入会识别一次图中的文字：

| 操作 | 行为 |
|---|---|
| 拖动鼠标 | 划选文字（字符级，可跨行），**松开即复制** |
| 双击 | 选中光标下的整词 |
| `Ctrl+A` / `Ctrl+C` | 全选 / 复制当前选区 |
| `Esc` | 退出选择文字模式 |

> 之所以用工具条按钮而不是直接拖动：贴图窗的左键拖动已经用于**移动窗口**，两种手势若靠"拖多远"隐式区分会难以预期。进入模式后光标变为 I 形，此时拖动才是划选。
> 划选高亮由 OCR 词框直接算出，与鼠标命中测试共用同一套坐标，因此"点哪里、哪里亮"始终一致；OCR 只在首次进入模式时跑一次并缓存，拖动过程不重复识别。
> 系统引擎路径的小字增强会把放大后的词框按倍率还原回原图坐标；PaddleOCR 路径的词框本就由引擎在输入位图坐标系里给出。因此无论走哪条引擎、有没有放大，划选位置都对得上。

> 走 PaddleOCR 时不需要任何系统 OCR 语言包；只有回退到系统引擎时才依赖它。若那时提示「未安装识别语言包」，请在「设置 → 时间和语言 → 语言和区域」里为目标语言添加「光学字符识别」功能。
> 目标程序以管理员身份运行时，OneBox 也需以管理员身份运行，否则无法对其注入滚动事件。

## 在贴图上标注

点编辑栏最左侧的「选择工具」按钮（▭）后，在图片上拖动即可画框；点「箭头」按钮（↗）后，从起点拖到指向位置即可画箭头；点「文字标注」按钮（T）后，在图片上点击即可输入文字。三种工具互斥，且都是**单次操作**：画完一个框/箭头、或提交/取消一次文字输入后自动退出，工具按钮恢复非高亮，拖动贴图和双击关闭随即可用；要继续编辑需再次点工具按钮。未开始操作时，再次点击当前工具按钮或按 `Esc` 也可退出。

| 操作 | 说明 |
|---|---|
| 选择工具 | 可选矩形/椭圆；在图上按住左键拖动，松开后提交并自动退出。小于 4×4 像素的误触会被忽略 |
| 箭头 | 从起点按住左键拖到指向位置，松开后提交并自动退出；小于 8 像素的误触会被忽略 |
| 边框/箭头颜色 | 8 色预设色块；框选与箭头共用，点击色块立即生效 |
| 边框/箭头粗细 | `−/+` 步进调整 1–8 像素，默认 2；框选与箭头共用 |
| 文字标注 | 点击图片出现文本框；支持多行，`Ctrl+Enter` 提交，点击框外提交，`Esc` 取消；提交或取消后自动退出 |
| 文字颜色/字号 | 8 色预设色块；字号 `−/+` 步进调整 10–72 像素，默认 20 |
| 撤销 | 工具条 ↶ 或 `Ctrl+Z`/`Alt+Z`，按添加顺序逐条移除；无标注时按钮不可用 |

> 点击编辑栏时贴图窗会临时允许激活，以便直接按 `Ctrl+Z` 撤销；只点击或拖动图片本身仍保持“不抢焦点”，不会打断下方应用。
> 标注是**非破坏性**的：只在贴图上叠加显示，不会裁剪原图；保存时按原图像素尺寸压平进图片。标注坐标以原图像素为准，因此缩放贴图、改变窗口大小或跨 DPI 屏幕移动时，标注会跟着图片一起缩放。
> 标注样式按贴图实例保存，不写入设置；关闭贴图后标注随之丢弃。当前版本只支持新增与撤销，不支持移动/缩放已有标注或再次编辑已有文字。
> 文字输入需要键盘焦点，贴图窗会临时允许激活，提交/取消后恢复“不抢焦点”并尽量把前台交还给编辑前的窗口。

## 实现要点

- **贴图置顶保活**：单纯设置 `WS_EX_TOPMOST` 不够，其他程序切前台仍会盖住。周期保活只做 `SWP_NOZORDER` 确认，**不**改 Z 序——多张贴图各自周期插队会形成循环争抢（画面闪烁）。只有用户主动操作（点击/拖动/新建贴图）才允许插到置顶组最前
- **滚动拼接用带容差的行剖面**，而不是量化签名：平滑滚动会产生亚像素位移与重绘抖动，量化后的精确比对实测匹配率常年为 0。锚点块允许 15% 的行不匹配以吸收噪声
- **系统引擎的小字增强**（仅回退到 `Windows.Media.Ocr` 时走这条路）：行高 < 20px 时把文字区域按 2-3 倍**双线性**放大后重识别（最近邻会把"订单编号"认成"订解号"），且**只在放大后识别出的字数确实更多时才采纳**，避免为了"看起来更清晰"而丢字
- **跨线程像素安全**：需要放大时先把来源位图固化成独立位图，因为 `await` 后代码会切到线程池，而解码得到的 `BitmapFrame` 有线程亲和性，跨线程读像素会抛"调用线程无法访问此对象"
- **识别结束必须回到 STA**：写剪贴板（OLE）与建窗口都只能在 UI 线程，因此识别流程刻意全程 `ConfigureAwait(true)`；耗时的识别本身在 WinRT 里异步完成，不卡 UI
- **划选是纯几何计算**：OCR 只在首次进入「选择文字」模式时跑一次，词框缓存挂在贴图窗上（关闭即释放），之后拖动划选与命中测试共用同一套坐标
- **截图前隐藏自己**：先把本插件的贴图与设置窗藏起来并等一帧（`DispatcherPriority.Render` + 80ms），否则刚 Hide 就抓图会抓到残影
- **OCR 双引擎**：`OcrService.RecognizeAsync` 先看 `PaddleOcrService.IsAvailable`（模型是否齐全），可用就走 PaddleOCR，否则或失败时回退系统引擎；两条路都产出同一个 `OcrOutcome`，版面与文本整理链路完全共用，上层无感
- **PaddleOCR 预处理不能用默认预设**：`RapidOcrNet` 的 `RapidOcrOptions.Default` 会把长边压到 1024。实测一张 875×4000 的长图因此一个文字块都识别不出来（13px 的字被压到约 3px）；改用短边自适应的 `PythonCompat`（`ImgResize=0`）后同图可出 179 块、小字截图命中率也从 14/20 升到 18-20/20。因此 `BuildOptions` 固定 `ImgResize=0`，只用 `LimitSideLen` 对应「小字图像增强」开关（开 = 736，关 = 0）
- **PaddleOCR 初始化昂贵**：RapidOcr 实例非线程安全且要加载三个模型（数百毫秒），因此懒加载单例 + 锁串行化，识别放线程池；模型不入库，由 `PrepareModels.ps1` 下载（`RapidOcrNet` 包只带 latin 识别模型，中文 rec 模型与字典要另下），缺失时静默回退
- **段落还原靠自己**：系统引擎的 `OcrResult.Text` 会把所有行用空格拼成一行，因此文本一律由版面几何聚类后的行生成，并按行距插入空行分段（`OcrLayout.DocumentText` + `OcrText.NormalizeDocument`，后者刻意保留空行）
- **剪贴板重试不阻塞 UI**：`ClipboardSupport` 在剪贴板被占用重试时用消息泵等待（`Dispatcher.PushFrame`）而不是 `Thread.Sleep`，等待期间贴图窗仍能拖动与关闭
- **标注显示与导出同源**：`PinAnnotationRenderer` 同时被贴图上的 `AnnotationView` 与 `PinWindow.ComposeImage()` 调用，屏幕显示和复制/保存/OCR 的合成图不会出现“看上去在这里、导出却偏了”的漂移
- **箭头头部单独绘制**：线条画到箭头底边，再用实心三角形填充尖端；头部长度按图片像素计算并限制在线段长度内，短箭头也能看清指向
- **编辑时临时允许激活**：贴图窗平时带 `WS_EX_NOACTIVATE`；点击编辑栏或进入文字编辑时临时清除，失焦后恢复，既让 `Ctrl+Z` 可用，又不影响点击/拖动图片时的“不抢焦点”
- **标注变化即失效 OCR 版面**：标注会改变合成图，`AnnotationsChanged` 清空插件侧的 `OcrLayout` 缓存；识别期间标注又变化时用 `AnnotationVersion` 丢弃过期结果
- **纯逻辑可单测**：文件名模板、滚动拼接、行剖面、OCR 版面/选区/文本整理、贴图标注的几何/颜色/撤销栈、设置声明的边界校验都在 `.Core` 里，测试见 `tests/OneBox.Tests/`

```
  TopmostPolicy（是否允许改变 Z 序的判定）
```

`models/v5/` 与 `PrepareModels.ps1` 不入库：跑一次脚本下载 PP-OCRv5 中文识别模型与字典（约 16 MB）后，构建会自动把它们复制到输出目录的 `models\v5\`。

> 模型缺失时构建会给出明确警告（`CheckOcrModels`），因为缺了中文模型插件会**静默回退**系统引擎、识别质量明显下降；要让它直接失败可加 `-p:_RequireOcrModels=true`。
> 发布另有两道保险：csproj 的 `CopyOcrModelAssets` 用裸 `Copy` 把工程内模型无条件拷进发布目录（绕开 MSBuild 发布增量缓存——该缓存一旦把文件记为"已发布"，之后即使文件从输出目录消失也不会补回），两个发布脚本也会在发布前清空 `plugins\<id>\`、并校验产物里 4 个 OCR 文件齐全（缺任一个即报错终止）。
