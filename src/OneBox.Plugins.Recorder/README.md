# 录屏

OneBox 的轻量录屏小工具。定位是**随手记录操作过程**，不是录制高清视频：
默认 10 帧/秒、550 kbps、最大宽度 960，输出 MP4 每分钟约 4.7 MB（含声音）。
全屏或框选一块区域录制，可同时录系统声音与麦克风，录制中有迷你悬浮控制条。
如果这次想要原始像素，可以把画质切到「原始分辨率」；停止后再决定是否压缩、压到哪一档，
把「录什么画质」和「最后留多大」拆成两步。

## 使用

| 操作 | 入口 |
| --- | --- |
| 开始 / 停止录制 | 全局热键 `Ctrl+Alt+R`，或托盘菜单「录屏 → 开始录制 / 停止录制」 |
| 区域录制 | 托盘菜单「录屏 → 区域录制…」，拖动框选后自动开始 |
| 暂停 / 继续 | 悬浮控制条上的暂停按钮，或托盘菜单「录屏 → 暂停录制 / 继续录制」 |
| 选择压缩保存 | 停止后弹出的「保存录屏」窗口：保持原画质，或选省空间/标准/清晰再转码 |
| 打开录制目录 | 托盘菜单「录屏 → 打开录制目录」 |

- 全屏录制默认录**鼠标所在的那块屏幕**，可以在设置里改成「主屏幕」。
- 悬浮控制条显示计时、暂停和停止，可以拖动到任意位置；它不会被录进画面。
  关闭「显示悬浮控制条」后，只能用热键或托盘菜单停止。
- 录制结束会先弹出「保存录屏」窗口（可在设置里关闭）；默认保存在插件的
  `data/plugin-state/recorder/recordings/` 下，按 `录屏_yyyyMMdd_HHmmss.mp4` 命名。
  压缩后的文件在原名后加目标宽度，例如 `录屏_20261021_111008_960w.mp4`。
- 区域录制一次只录一块屏幕：框选跨屏时，取重叠面积最大的那块，其余部分被裁掉。
- 同一时刻只允许一路录制；录制中再按热键只会停止当前这路，不会叠加。

热键可以在工具箱的「热键」页里改；被其他程序占用时，插件状态会显示「1 个热键被占用」，并在日志里写明组合键。

## 设置项

设置都在宿主「设置中心 → 录屏」里，改完对下一次录制生效。

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 保存目录 | 空（插件数据目录的 `recordings`） | 留空即用默认目录 |
| 录制完成后询问是否压缩 | 开 | 关闭则停止后按录制画质直接保存，不弹保存窗口 |
| 录制完成后定位到文件 | 关 | 保存完成后打开资源管理器并选中文件 |
| 画质档位 | 省空间 | 录制时的码率与最大宽度，见下表；含「原始分辨率」 |
| 帧率 | 10 | 8 / 10 / 15；静态演示用 8 就够 |
| 录制系统声音 | 开 | 扬声器回环，录正在播放的声音 |
| 录制麦克风 | 关 | 可与系统声音同时录，底层自动混音 |
| 录制鼠标指针 | 开 | 关闭后成片里看不到鼠标 |
| 全屏录制范围 | 鼠标所在的屏幕 | 或固定主屏幕 |
| 显示悬浮控制条 | 开 | 关闭后靠热键/托盘菜单停止 |

### 画质与体积

码率是 CBR（恒定码率），音频固定 AAC 96 kbps；估算值含约 2% 的容器与编码开销。

| 档位 | 视频码率 | 最大宽度 | 约每分钟（含声音） |
| --- | --- | --- | --- |
| 省空间 | 550 kbps | 960 | 4.7 MB |
| 标准 | 850 kbps | 1280 | 6.9 MB |
| 清晰 | 1.4 Mbps | 1600 | 10.9 MB |
| 原始分辨率 | 按像素与帧率自动算 | 不缩放 | 1080p/10fps 约 19 MB；4K/10fps 约 75 MB |

输出尺寸按源画面等比缩小到「最大宽度」，宽高都取偶数（H.264 要求），**不放大**。
因此录一小块区域时文件会明显更小；录 4K 屏幕也会先降到 960/1280/1600 宽再编码。
原始分辨率档按「像素数 × 帧率 × 0.12 bit」估算码率（最低 800 kbps、最高 20 Mbps），
1080p/10fps 约 2.5 Mbps；它的价值是给后续压缩留出原始素材。

### 保存时压缩

停止录制后会弹出「保存录屏」窗口：

- **保持当前画质（不压缩）**：保留刚录好的文件，不再转码。
- **压缩后保存**：从比当前画面更小的档位里选一个（省空间 / 标准 / 清晰），
  插件用系统转码器生成新的 MP4；目标分辨率按源画面等比缩放，不会放大。
- **压缩成功后保留原始文件**：默认不勾选，转码成功后删除原始文件；勾选则两份都留。
- 转码失败或取消时，原始文件一律保留；窗口里能选的目标、预计体积都会实时显示。

例如原始分辨率录了 1920×1080，选「省空间」会得到 960×540 的 `_960w.mp4`，
默认码率 550 kbps；如果当前录制已经是 960 宽，没有更小的档位，停止后就不再
弹压缩选择，直接按当前画质保存。转码是二次编码，耗时随视频长度增加，比录制本身慢一些。

## 技术实现

- **采集**：`ScreenRecorderLib`（MIT）调用 Windows.Graphics.Capture 抓屏幕，关闭 Windows 11 的捕获黄框。
- **编码**：Media Foundation 的 H.264 编码器 + AAC 音频，直接写成 MP4；固定帧率保证
  静态画面下成片时长仍然准确。
- **保存时压缩**：`Windows.Media.Transcoding.MediaTranscoder` 按目标宽高/码率重新编码，
  不额外携带 ffmpeg；为了调用这个 Windows API，插件引用 Windows SDK 投影，
  框架依赖发布后 exe 约 26 MB（与截图插件的 OCR 依赖同量级）。
- **音频**：WASAPI 回环录系统声音、WASAPI capture 录麦克风；两者都开启时由库混音。
  设备一律用系统默认设备——换设备去 Windows 声音设置里改默认，插件不额外维护一份设备列表。
  找不到设备时降级为只录画面，并写日志/状态提示，不会因此让整次录制失败。
- **悬浮控制条**：开录前把窗口句柄交给 `SetExcludeFromCapture`，所以停在录制区域上也不会入镜；
  `ShowActivated=false`，按热键开始录制不会把焦点从你正在操作的窗口抢走。
- **选区**：独立遮罩窗覆盖整个虚拟屏幕，按物理像素换算（进程声明 PerMonitorV2），
  确认后把虚拟屏幕坐标裁进目标显示器，再换成录屏库要求的显示器局部坐标。
- **发布布局**：录屏后端是 x64 的 C++/CLI 混合程序集，不能打进单文件包，因此插件目录里
  除 `OneBox.Plugins.Recorder.exe` 与 `plugin.json` 外还有一个 `ScreenRecorderLib.dll`；
  发布脚本会原样带走，不需要额外配置。
- **退出兜底**：宿主停用插件/退出时先 `Stop()` 并最多等 4 秒让文件落盘，避免留下坏文件；
  正常停止若 25 秒仍未收到完成回调，也会明确提示而不是永远停在「正在保存」。

## 数据文件

都在插件数据目录 `data/plugin-state/recorder/` 下：

```
settings.json           插件设置（宿主只回传改动，插件自己保存）
recordings/             默认录制目录
recorder.log            插件自己的诊断日志
recorder-native.log     录屏库的原生日志（Warn 级别）
```

## 已知限制

- 依赖 Windows 自带的 Media Foundation 编码器与 **VC++ 2015-2022 x64 运行库**
  （[官方安装包](https://aka.ms/vs/17/release/vc_redist.x64.exe)）；缺少运行库时插件启动/录制会失败，
  日志里会写明。目标系统需 Windows 10 1803+（Windows.Graphics.Capture）。
- Windows 10 2004 以前的系统不支持 `WDA_EXCLUDEFROMCAPTURE`，悬浮控制条可能出现在录像画面里；
  遇到这种情况可以在设置里关闭「显示悬浮控制条」。
- 多屏且各屏缩放比例不同时，选区坐标以遮罩窗口所在屏的缩放为准，跨屏选区可能有偏移；
  单屏或各屏缩放一致时不受影响。
- 受 DRM 保护的画面、独占全屏游戏可能录成黑屏；这是系统捕获 API 的限制。
- 区域录制只覆盖一块屏幕；跨屏选区会被裁到重叠面积最大的屏幕内。
- 音频设备使用系统默认；录制过程中切换默认设备不会自动跟随。
- 停止后的压缩是二次转码，视频越长越慢；压缩成功后默认删除原始文件，需要保留就在保存窗口勾选。
- 不做摄像头、鼠标点击高亮、直播推流——这个插件只做「小而够用」的本地录屏。

## 开发

```powershell
dotnet build OneBox.slnx
dotnet test OneBox.slnx
```

纯逻辑（画质档位与体积估算、监视器布局、文件名、设置声明）在
`OneBox.Plugins.Recorder.Core`，对应测试在 `tests/OneBox.Tests`。
录屏后端是 x64 的 C++/CLI 程序集，插件项目固定 `PlatformTarget=x64`；
引用时绕过包的 `build` targets，避免整解决方案按 AnyCPU 构建时报平台错误。
