# 滚动截图 v2：安全采集、相邻帧配准与离线回放

## 能力归属与架构

本功能属于**截图插件特定能力**：原始截图像素的滚动配准与长图组装不构成宿主平台契约，其他插件不应复用截图业务。纯逻辑置于 `OneBox.Plugins.Screenshot.Core`，WPF/Win32 适配留在截图插件；回放独立位于 `tools/scroll-replay/`，不增加 NuGet，不改宿主接口。

- `ScrollCaptureController`：无 UI 依赖的一次性控制器，通过 `IScrollCaptureSource` 获得 `ScrollCaptureFrame`、滚轮发送结果、目标有效性和取消状态，返回 `ScrollCaptureResult`。捕获尝试数/时长受限；只根据已确认位移推进基准，不跨失败帧跳接。
- `ScrollCaptureSession` / `DesktopScrollSource`：真实 Windows/WPF 适配，检查选区和目标窗口、等待按键释放、采集稳定帧并发送滚轮。初始步长一格（120），按选区高度约 0.45 校准；旧设置 `ScrollWheelNotches` 保持 key，但语义为步长上限（1–6 格），不是首步固定滚动量。
- `ScrollFrameRegistration`：只比较相邻**已接受的原始帧**。二维多列灰度/梯度筛选候选，重叠正文区域 BGRA 像素用于确认；匹配时忽略左右最多 16px 的窄边缘 gutter，避免浏览器滚动条/滑块干扰，输出像素不裁切。固定头尾须由边缘区块内部正文纹理确认，不能把窄滚动条加留白误报成固定栏。多解、低纹理、真正固定头尾等不可靠输入仍拒绝，不凭白底相似或“新增内容”推测位移。
- `ScrollStitcher`：保留 `Add(byte[] pixels, int height, int bytesPerRow)` API；确认后才追加原始新行，失败不推进原帧基准或增加已接受 `FrameCount`。高度/内存预算达到上限时保留此前内容，拒绝不安全追加；默认预算 256 MiB，不包含调用者自行保留的副本。
- 控制条放在选区外，无安全位置则隐藏；**F8 完成并预览，Esc 取消**。取消丢弃结果。F8 只完成当前会话，不代表已经验证全文完整。
- `ScrollOcclusionGuard`：捕获前后保守遍历目标上方可见窗口与完整选区的矩形交集，透明/分层窗口也不放行；这是瞬时检查而非原子屏幕快照。用户移开鼠标时暂停等待至多 8 秒，不抢回光标。异常/目标丢失等部分结果须默认否的确认后才预览/复制。

## 结束与“到底”的含义

没有可靠的页面底部传感器，不能仅凭静止画面确认到底：可能是输入未被接受、目标失焦、内部滚动容器、动画或权限问题。只能报告“无进一步位移”，**未知不是成功，也不是确认完整**。

`ScrollCaptureEndReason` 区分 `Finished`、`Cancelled`、`UnableToScroll`、`NoFurtherMotion`、`Incomplete`、`TargetLost`、`CaptureFailed`、`ScrollFailed`、`InvalidFrame`、`FrameLimit`、`DurationLimit` 和 `StitcherLimit`。当前这些结果均不宣称 `IsComplete=true`；`CanExport` 仅表示存在可导出的已确认内容，不表示全页面完整。正文连续编号与最终 END 标记有助于人工核对。

## 诊断开关与隐私

**默认不自动保存真实帧。** 发生 `Incomplete` 时，可在失败后的确认框中明确同意保存本地诊断包（默认否，不上传）；内存最多保留24MiB/4帧的首帧及最近采样，帧过大则不缓存，取消则清空。保留的是采样子集，不保证连续，`session.json` 会标记 `sampledSubset=true`，不能当成完整滚动序列。

如需完整逐帧诊断，显式设置 `ONEBOX_SCROLL_DIAGNOSTICS=1`。在启动 OneBox 的进程环境中设置；关闭后重新启动，避免继承旧环境值。

```powershell
$env:ONEBOX_SCROLL_DIAGNOSTICS = '1'
# 从此环境启动 OneBox；不要把敏感页面用于诊断。
# 排查后关闭，再启动下一次会话：
Remove-Item Env:ONEBOX_SCROLL_DIAGNOSTICS
```

启用时写入 `AppPaths.DataDirectory/scroll-diagnostics/<会话时间戳>/`：

- `00001.png` 等原始选区帧：每次稳定判定完成或等待超时的采样结果，可能包含未接受/不稳定帧。
- `events.jsonl`：帧号与稳定性、输入发送结果等事件，辅助排查控制流程。
- `session.json`：版本、选区尺寸与 `minMatchRows`，便于离线使用相同匹配参数。

取消时会先等待本次采样/诊断写入退出，再删除本次会话诊断目录，防止取消后继续写入；若文件被外部程序占用导致删除失败，日志会明确提示需手动删除。

**PNG 是真实页面内容**，可能含账号、聊天、文档、地址等敏感信息；路径和事件也可能泄露使用习惯。本地保存不等于已脱敏。分享前逐帧检查/脱敏，限制目录访问，排查后手动删除；不要上传、提交版本库或作为普通日志收集。回放输出同样敏感。不开启开关就不会自动产生可回放帧目录。

## 独立离线回放 CLI

在 OneBox 根目录、Windows .NET 8 SDK 环境中运行：

```powershell
dotnet build tools/scroll-replay/ScrollReplay.csproj
dotnet run --project tools/scroll-replay -- <帧目录> [输出PNG] [可选期望新增位移CSV]
# CSV 可是文件路径，也可直接传逗号分隔字符串：
dotnet run --project tools/scroll-replay -- .\frames .\replay.png '120,0,80'
```

项目为 `net8.0-windows` + `UseWPF`，从 `../../src` 引用 Screenshot Core；显式 namespace、`[STAThread] Main`，不启动 Application、窗口、浏览器或真实滚轮。WPF `PngBitmapDecoder` 在 OnLoad 模式读取并转换 BGRA32，释放输入文件。

只读取目录顶层 PNG（扩展名不区分大小写），按**文件名 StringComparer.Ordinal** 排序；请使用补零编号，`10.png` 会排在 `2.png` 前。尺寸必须完全一致，不缩放、不裁切。默认输出 `<帧目录>/replay.png`，输出路径排除于输入列表；建议输出放在帧目录外，不要混入旧结果图。若有 `session.json` 则读取 `minMatchRows`，缺省 24；无效值直接失败，配置以 JSON 输出。

标准输出为 JSON Lines；每个处理帧包含 `status`、`appended`、`overlap`、`LastScrollDelta`、`LastMatchedRows`、`LastRequiredRows`、文件名及总高。First/Appended 继续，NoChange 允许继续（下帧可能恢复滚动），LimitReached 正常停止但标注 partial。其他状态（包括 NoOverlap、Ambiguous、InsufficientTexture、FixedContent、MemoryLimitReached 和未来新增失败状态）**立即停止，不跳过继续喂帧**；解码、尺寸、参数、导出失败也返回非 0。

只要已有接受行，失败后也尝试导出部分 PNG；部分图不能当作完整成功。最终 summary 包含 `exitCode`、`partial`、`processed`、`frameCount`、输出路径和固定 false 的 `bottomConfirmed`。退出码 0 仅表示离线配准未遇失败，不保证全部帧已回放或页面已到底；1 为处理/配准/导出错误，2 为严格期望验证失败，64 为用法错误。首帧都不能接受时无 PNG 可导出。

### CSV 与全像素验证

CSV 为非负十进制整数，以逗号或换行分隔，不含表头。N 张输入帧允许 N 个数（首个必须等于首帧高度）或 N-1 个数（只列首帧后的新增行数，首帧全高自动补入）。位移是每次**新增行数**，不是累计位置；未移动用 0。

每次核对 `AppendedRows`；用期望位移定位重叠区，对所有行、所有列、BGRA 四通道逐字节比较重叠，再用期望新行构建参考长图，与 `BuildBgra()` 全量比较。无取样、无容差、无只比高度。失败后立即停止；PNG 可能包含最后一次配准已接受但严格校验未通过的行，必须仅当诊断证据。

此模式适合同一原图裁切的确定性帧或已知真实位移数据。真实页面光标、抗锯齿、动画、时间文本可能使严格校验失败，不等同于容差匹配必然错误。没有 CSV 时只报告诊断，不声称通过全像素真值验证。回放**不复现**控制器稳定性等待、恢复输入、目标丢失或真实底部判断；需结合 events.jsonl 查看因果。

## 真实失败样本分析（2026-10-19）

用户明确同意保存的 1913×909 三帧样本：首帧到第二帧前进100px，匹配正文逐像素一致；第二帧到第三帧前进300px，文字布局相同但重叠正文约1.53%像素RGB差值超过8。以亮度180提取文字前景，正确300px位移IoU约0.969，偏移299/301仅约0.539；水平边缘IoU正确约0.939，错一行约0.564。旧逐像素否决及稀疏绝对灰度粗筛不能容忍该渲染变化；必须以充分的局部纹理几何证据验证，不能简单提高RGB容差。真实图片仅存用户本地诊断目录，不作为源代码测试资产提交。进一步局部分析发现，新帧标题前增加约14×15px链环悬浮图标，旧帧相同位置为空白；这与文字抗锯齿重绘是两个独立干扰。若启用极小覆盖物例外，必须记录边界并限制为单个、孤立、单侧空白的紧致对象，正文替换不适用。仅凭像素无法数学区分所有同样大小的新增文字与图标，该限制必须作为能力边界而非完整性保证。

### 针对该诊断包的修复与验证

新增独立的抗重绘路径：只在足够长的重叠区、多个纵横分区与大量纹理微块提供一致位移证据时使用二维梯度归一化验证；不再要求文字每个RGB像素不变，仍保留严格BGRA路径、alpha约束与多候选歧义拒绝。诊断记录重绘分数、纹理块数及小覆盖物边界。用户三帧离线回放确认新增100px、300px，输出1913×1309；约1651个微块的平均相关约0.9971，单个覆盖物边界482,456,14,15。导出的长图与首帧+第二帧末100行+第三帧末300行的原始RGBA条带逐字节一致，不缩放、不改色、不重采样。最终同尺度128行位移唯一性验证峰值约0.99065，次峰约0.10966；全量584项测试通过（新增12项重绘/替字/删行/缩放/横移/alpha/单双覆盖物/周期拒绝）。该包是采样子集，只验证这三帧的拼接，不代表全文或实时自动滚动已验收。

### 第二次真实失败：底部窗口边框（2026-10-19 15:22）

用户同意保存的 1915×917 样本，originalFrameIndices=[1,2,8]，是采样子集。首帧到第二帧正文前进100px，内部814行BGRA完全一致；旧帧最底3行是固定窗口边框（201/247/255中性灰），被误计为重叠正文而触发 NoOverlap。第三张与第二张逐字节相同。本次不推断缺失的第3～7帧，也不扩大控制器恢复策略。

在 Screenshot.Core 内识别两帧紧贴底部、一致且不透明的1～3行极薄中性边框：窄侧边gutter外每行必须完全同色，包含160～224灰线，其下仅允许240以上亮色。正文仍以原有阈值、纹理和歧义规则配准；有效正文重叠不足minimumRows仍拒绝。诊断 BottomBorderRows 标识边带厚度；OverlapRows为原帧坐标，MatchedRows/BestCoarseOverlap为排除边带后的有效正文坐标，LastRequiredRows不含边带。

组装不裁切或重采样，使用新帧[overlap-border,overlap)原始行覆盖旧输出尾部，再追加[overlap,height)；原始基准不变。跨多个1px短chunk也正确覆盖；高度/内存拒绝前不修改结果，List容量亦在提交前预分配。最终帧最底仍保留原窗口边框，侧边滚动条仍是原图，不承诺擦除全部浏览器外框。仅凭像素无法绝对区分完全相同的正文灰线和窗口线；这是严格限制的启发式边界，不是页面完整性证明。

## 局限与验证边界

仅支持向下纯纵向滚动；横向位移、变宽、DPI/缩放改变、动画、虚拟列表重排、异步加载、强周期纹理及固定内容均可能被保守拒绝。未确认重叠时不能降低阈值、跳帧、猜位移或用画面新颖度绕过；应调整选区、减少步长、等待稳定或换静态页面重试。大图受高度、整数数组与内存预算限制；严格 CSV 模式还额外保留参考图和导出缓冲。
